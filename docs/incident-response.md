# Incident response

Severity 1 includes incorrect emergency behavior, cross-user disclosure, leaked credentials/tokens, demo data reaching production, or a materially false verified claim. Immediately disable the affected feature or record, preserve audit evidence, rotate exposed credentials, and keep static 108/102 actions available. Do not silently substitute other medical guidance.

The incident owner records detection time, scope, affected versions/records, containment, notification decisions, recovery validation, and follow-up actions. Facility revisions, protocol versions, application releases, and database migrations have independent rollback paths. Restore tests must verify RLS and public-data filters before reopening.

Lower-severity wrong-number, stale-hours, source, translation, and routing incidents enter the verification queue with an owner and deadline. Post-incident review must update fixtures, verification checklists, monitoring, or runbooks—not only the immediate record.
