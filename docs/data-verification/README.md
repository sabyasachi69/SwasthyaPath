# Facility verification standard

A `verified_real` record requires an official or facility-owned source, coordinates checked against the address, a tested public phone number, service claims tied to evidence, timing semantics that do not imply live availability, English/Odia name review, verifier identity, `last_verified_at`, and `valid_until`.

Editors create private drafts. A different verifier checks contact, location, source, and translation before approval. Publication is transactional and audited. User reports create review work only; they never edit public data. Records are flagged 30 days before expiry and disappear from public search after expiry.

The initial inventory must list every prototype facility, doctor, schedule, distance, service, and medical claim as unverified. Doctor names, precise schedules, capacity, beds, medicines, blood stock, queues, and availability are excluded unless a future approved data contract supports them.

Minimum launch set and source worksheet remain human-owned deliverables. The database deliberately starts empty rather than presenting unsupported claims.
